# meeting-dev (테스트 전용 플러그인)

> **테스트 환경 전용입니다.** 대시보드를 로컬 PC(루프백 `127.0.0.1`)에서 직접 띄워 시험할 때만 사용하며, Dataiku 등 실제 서비스로 전환하면 이 플러그인을 제거하세요. 정규 플러그인 `meeting`은 이 플러그인 없이도 동작합니다.

대시보드 로컬 서버의 기동·정지·종료를 **사용자 승인 후에만** 수행합니다.

## 명령
| 명령 | 동작 | 승인 |
| :-- | :-- | :-- |
| `/meeting-dev:ensure [이어갈 작업]` | 꺼져 있으면 알리고 → 승인 → 기동 → 원래 작업 재개 | 필수 |
| `/meeting-dev:start` | 서버 기동 | 필수 |
| `/meeting-dev:stop` | 이 도구가 기동한 서버만 종료 | 필수 |
| `/meeting-dev:terminate` | 켜져 있는 서버를 기동 주체와 무관하게 종료(대상이 대시보드 서버인지 검증) | 필수 |
| `/meeting-dev:help` | 사용법과 테스트 워크플로우 | - |

## 필수 설정
| 설정 | 기본값 | 설명 |
| :-- | :-- | :-- |
| `dashboard_root` | (비어 있음, **필수**) | `src/middle/server.js`가 있는 대시보드 폴더의 절대경로. 미설정 시 기동 불가(코드 24) |
| `port` | `3000` | 로컬 포트 |

환경변수: `MEETING_DASHBOARD_ROOT`, `MEETING_DASHBOARD_PORT`

## 안전장치
- 모든 기동·정지·종료는 승인 후 `--confirm`으로만 실행되고, 그 전에는 실행 내용만 보여 줍니다(dry-run).
- `terminate`는 포트를 쓰는 프로세스가 대시보드 서버(`node src/middle/server.js`)로 확인될 때만 종료합니다(코드 22).
- 종료 시 서버가 강제 종료되고 메모리의 편집 내용은 초기화됩니다(서버는 인메모리 전용이라 파일 손실은 없음).

## 요구사항
Windows, Node.js 18 이상 (PowerShell, `taskkill` 사용)

종료코드: 20 포트 충돌 · 21 기동 시간 초과 · 22 종료 대상 불일치 · 23 종료 실패 · 24 대시보드 폴더 미설정/오류 · 25 원격 대시보드(Vercel 등)에 연결되어 있어 기동하지 않음

`meeting` 플러그인을 `/meeting:connect` 로 원격 주소에 연결하면 `start`/`ensure` 는 로컬 서버를 켜지 않습니다. 로컬로 돌아가려면 `/meeting:connect --reset`.
